# Part 3 — Wire Kevin context into program generation

Connect `kevin-context-service.ts` to the selected canonical authenticated generation workflow in `program-build-service.ts` or the actual production equivalent.

Do not connect it to unauthenticated or external API generation by default.

## Required order of operations

The generation flow must be:

```text
1. authenticate user
2. resolve tenant or organization
3. validate generation request
4. load current TrainChat program constraints
5. load current TrainChat safety restrictions
6. load current TrainChat preferences
7. evaluate Kevin master feature flag
8. evaluate KEVIN_CONTEXT_RETRIEVAL_ENABLED
9. evaluate training-context capability
10. evaluate memory consent
11. create pseudonymous user identifier
12. request bounded Kevin context
13. merge only validated optional context
14. call the existing TrainChat generation engine
15. run all existing deterministic validation
16. save through existing transaction and advisory lock
17. store context provenance
18. enqueue sanitized generation event
```

Kevin must be optional.

Any Kevin error must result in an empty context object and normal TrainChat generation.

## Context priority

Apply context in this order:

```text
1. current explicit user request
2. safety restrictions and contraindication controls
3. current program structure
4. current equipment availability
5. current session-duration requirements
6. explicit preferences stored in TrainChat
7. optional Kevin memory
8. default generation behavior
```

Kevin context must never override items 1–6.

## Allowed Kevin context

Kevin may provide:

```text
preferred training style
preferred session duration
equipment preferences
preferred exercise categories
disliked exercise categories
prior accepted substitutions
preferred coaching tone
recurring edit patterns
broad adherence patterns
prior accepted program modifications
```

Kevin must not provide or override:

```text
medical diagnoses
raw injury notes
pain reports
medications
pregnancy information
raw coach notes
email addresses
phone numbers
billing details
authentication data
another user’s memory
another organization’s memory
arbitrary exercise IDs
arbitrary database records
```

## Safe prompt integration

Do not append raw Kevin output directly to the system prompt.

Create a structured and bounded prompt fragment.

Example:

```text
OPTIONAL SAVED TRAINING PREFERENCES

The following information is optional historical preference context.
It must not override the current user request, safety restrictions,
available equipment, program rules, or current session constraints.

- Preferred session duration: 45 minutes
- Preferred training emphasis: strength
- Previously accepted substitution pattern: split squat → step-up
- Coaching tone: concise

Use only relevant preferences. Ignore conflicts with the current request.
```

Escape or sanitize delimiter-breaking content.

Do not store or expose hidden chain-of-thought.

## Context request input

Use only minimal safe information.

Suggested input:

```ts

  equipmentCategories,

  traceId,

}
```

Do not send the full user prompt unless absolutely required.

Do not send raw names, emails, health notes, or full historical workouts.

## Provenance

# Part 7 — Capability enforcement

Require the correct capability for generation enrichment.

Suggested capability:

```text
program_generation_context
```

or use the existing canonical capability name from the repository.

Rules:

```text
disabled
→ no context request

observe
→ context may be retrieved and audited but must not alter generation

recommend
→ context may be surfaced as non-binding evidence

draft
→ context may influence a draft program, still fully validated

require_approval
→ no automatic user-facing use unless the existing workflow includes approval

auto
→ may enrich generation but can never bypass safety or validation
```

For the first live release, use:

```text

```

for general users and optionally:

```text

```

for one internal test account.

Do not silently treat `observe` as permission to modify the generated workout.

```text

```
